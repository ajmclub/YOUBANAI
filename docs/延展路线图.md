# 游伴 AI · 延展路线图

> **定位说明**：本文把商业计划书的 Phase 01–04 落地为工程任务清单与验收标准，并提供一份「短期可立即做的 10 个改进项」。每个 Phase 的「已完成」部分只列本仓库真实存在的能力与文件，未完成部分给出明确的交付物、涉及文件与可判定的验收条件。

- 当前版本：v1.0.0
- 当前规模（`tests/_inspect.txt`）：**12 景区 / 8 剧本 / 31 章 / 51 节点 / 63 任务 / 24 徽章 / 441 素材**（439 已入库 + 2 解析中）/ 6 用户 / 6 SKU
- 当前接口面：C 端 16 + B 端 24 + 系统 3 = **43 个操作**（其中 42 条挂在 `/api/` 下）；26 张表；8 个索引
- 验证状态：**五套验证全绿** —— 契约检查 0 问题 · 交付终检 60 项 · 真实浏览器 **147 项** · 接口自检 49 项 · 第二轮自检 130 项
  统一入口：`python tests/run_all.py --start`
- 第二轮新增（v1.1 增量）：云南《雨林寻踪》+ 苏州《园林谜题》两个完整剧本、C 端**家长模式 · 成长报告**、
  可观测性（结构化日志 + 指标接口 + 业务计数）、统一测试入口

## 0. 路线图总览

| Phase | 目标 | 一句话 | 状态 |
|---|---|---|---|
| **Phase 01** | 1 IP × 1 景区（大唐密令）产品验证 | 把「走到哪里，故事发生在哪里」跑通成可演示的闭环 | ✅ 已完成 |
| **Phase 02** | 1 IP × 10 景区 × 3 城市 | 从单景区样板扩到可复制的内容生产线 | ⏳ 待启动 |
| **Phase 03** | 多 IP × 100+ 景区 平台化 | 从「我们做内容」到「别人也能用我们的平台做内容」 | ⏳ 待启动 |
| **Phase 04** | 城市故事网络 / 全球化 | 从景区内容网络到城市级、跨语种的故事网络 | ⏳ 远期 |

Phase 之间的依赖关系：

```
Phase 01 单景区闭环（已完成）
   └─ 需要：多租户 + 内容审核 + 向量检索 + 设备网关
        └─ Phase 02 十景区三城市
             └─ 需要：IP 授权 + 分账结算 + 开放 API + 多角色权限
                  └─ Phase 03 平台化
                       └─ 需要：i18n + 离线包 + AR/定位增强 + 儿童数据合规
                            └─ Phase 04 城市故事网络 / 全球化
```

### 2.2 验收标准

| 验收项 | 标准 |
|---|---|
| 多租户隔离 | 租户 A 的接口在任意参数组合下都无法读到租户 B 的剧本、素材、游客数据（自动化测试覆盖） |
| 审核流 | `draft → review → online` 三步可走通；`draft` 剧本不出现在 `/api/c/explore` 与 `scenario` 接口 |
| 向量检索 | 「阿游，这座塔为什么是七层」这类无字面重合的提问，能返回包含「大雁塔 七层」语义的素材 |
| 设备网关 | 设备心跳可更新 `devices.online`；离线设备在后台显示为离线 |
| 10 景区可生产 | 每个景区都能用 `mode=full` 生成 ≥ 1 个剧本（章节 ≥ 3、节点 ≥ 6），且 `sources[]` 非空 |
| 3 城市可游玩 | 西安 / 北京 / 杭州三城各自有 ≥ 1 个 `online` 剧本，且地图与城市卡片状态正确 |
| 生成质量 | AI 生成剧本 100% 通过质量门禁，否则自动进入 `review` |
| 性能 | 单次 `mode=full` 生成 P95 < 3s（离线引擎）；批量生成 10 景区 < 60s |
| 回归 | e2e 自检 0 失败，新增多租户与批量生成用例全部通过 |

## 3. Phase 03 · 多 IP × 100+ 景区 平台化

**目标**：从「游伴自己生产内容」变成「景区/合作方也能在平台上生产内容」，并把钱的事算清楚。

### 3.1 技术任务清单

| # | 任务 | 现状 | 动作 | 涉及文件 |
|---|---|---|---|---|
| 1 | **IP 授权体系** | `characters` 表只有 1 条「阿游」，无授权信息 | 新增 `ip_licenses` 表（IP、授权方、授权范围、有效期、可售城市）；`skus` 关联授权；C 端只下发已授权的 IP 装扮 | `app/schema.sql`、`app/routers/admin.py`、`app/routers/c_end.py` |
| 2 | **分账结算系统** | `revenue_shares` 是配置文本，无结算单据 | 新增 `settlements` / `settlement_items` 表；按「潮玩 15%/85%、会员 30%/70%、SaaS ¥12,000/月」生成月结单；支持导出与对账 | 新增表 + `app/routers/admin.py` |
| 3 | **开放 API** | 全部接口是内部契约，无版本与鉴权 | 引入 `/api/v1/` 前缀与 API Key/OAuth；限流（按租户 QPS）；开放「素材上传 / 剧本读取 / 生成调用 / 数据统计」四类能力；发布 API 文档 | `app/main.py`、`app/routers/*`、`docs/API.md` |
| 4 | **多角色权限** | 无登录态，`user_id` 直传 | 角色划分为 平台运营 / 景区管理员 / 内容编辑 / 审核员 / 数据分析 / 家长；RBAC 中间件；操作审计日志 | 新增 `users_roles` / `audit_logs` 表 + 鉴权依赖 |
| 5 | **内容版本管理** | 编辑直接改行，无法回滚 | 新增 `scenario_versions`（快照 + 差异）；支持回滚与对比；发布走版本号 | 新增表 + `app/routers/admin.py` |
| 6 | **100+ 景区的内容规模化** | 12 景区 | 素材分片存储与索引；生成任务按景区分片并行；内容质量抽检机制 | `app/engines/story_engine.py`、任务队列 |
| 7 | **多区分库/读写分离** | 单 SQLite 文件 | 迁移到服务型数据库（PostgreSQL）或按租户分库；`db.py` 抽象成可替换的 Repository 接口 | `app/db.py`、`app/schema.sql` |
| 8 | **可观测性** | 只有 `/health` 与 print 日志 | 结构化日志 + 请求耗时埋点 + 关键业务指标（激活成功率、触发成功率、任务通过率、生成成功率）+ 告警 | `app/main.py`、中间件 |
| 9 | **数据合规基础设施** | 无 | 数据分级、加密存储、导出与删除接口（GDPR 式「删除我的数据」）、访问审计 | 多表 + 新增路由 |
| 10 | **成本核算** | 无 | 记录每次大模型调用的 token 与费用，按景区/剧本归集，纳入分账 | `ai_jobs` 扩展字段 |

### 3.2 验收标准

| 验收项 | 标准 |
|---|---|
| 授权合规 | 任一上架 SKU / 剧本都能追溯到有效的 `ip_licenses` 记录，过期授权自动下架 |
| 结算正确 | 一个月内任意一笔 C 端流水，都能在结算单中找到对应的分摊行，且总额守恒（平台 + 景区 = 流水） |
| 开放 API | 合作方用 API Key 可独立完成「上传素材 → 生成剧本 → 读取剧本」闭环，且有独立限流与配额 |
| 权限 | 5 类角色各自的越权尝试全部被拒绝（自动化用例覆盖） |
| 版本管理 | 剧本可回滚到任意历史版本，回滚后 C 端展示与后台一致 |
| 规模化 | 同时在线 100 个景区、单日 10 万次定位触发下，接口 P95 < 300ms |
| 可观测 | 核心 5 个业务指标可在监控面板查看，异常可自动告警 |
| 合规 | 提供「导出我的数据」与「删除我的数据」两个接口，且删除后 30 天内不可恢复 |

## 4. Phase 04 · 城市故事网络 / 全球化

**目标**：从「景区里的故事」升级为「一座城市的故事网络」，并走向多语种市场。

### 4.1 技术任务清单

| # | 任务 | 动作 |
|---|---|---|
| 1 | **i18n 多语言** | 全部文案（剧本、任务、UI、后台）走 key + 多语言包；`scenarios/nodes/tasks` 增加语言维度字段或独立翻译表；先做中英双语，AI 生成支持「按语言生成」 |
| 2 | **离线包** | 剧本 + 素材打包为可离线使用的资源包（含地图底图缓存），弱网/无网场景下仍可完成已下载剧本的任务；提供版本与增量更新 |
| 3 | **AR 相机** | 在节点剧情页接入 AR：识别建筑纹样/雕塑/文物后叠加线索；与现有 `photo` 判定打通（拍照 + 识别结果双向验证） |
| 4 | **定位增强** | 由「单点 GPS」升级为「GPS + 惯性 + 多点校验」；增加速度合理性校验与轨迹平滑，解决景区内 GPS 漂移导致的误触发/不触发 |
| 5 | **城市故事网络** | 引入城市级路线（跨景区串联成一日/两日故事线）；城市任务与城市徽章（对应已有 `badges.city` 字段） |
| 6 | **儿童数据合规** | 家长同意与监护流程、最小化采集、儿童数据单独存储与保留期限、内容分级与审核、可审计的访问控制 |
| 7 | **家长端** | 家长视角的成长周报、游玩轨迹、内容消费报告、时长管理 |
| 8 | **内容众创与审核** | 开放景区/学校/文旅局共创入口，配合分级审核与人审抽检 |
| 9 | **多端一致** | 小程序 / H5 / App 三端共用同一份 API 契约与资源包格式 |
| 10 | **全球内容本地化** | 多语言 + 多时区 + 多币种 + 本地文化适配（避免只用中国历史题材的隐喻） |

### 4.2 验收标准

| 验收项 | 标准 |
|---|---|
| 多语言 | 中英双语下，C 端 5 页 + 节点页 + 后台全部文案无中文残留（可自动扫描） |
| 离线可用 | 飞机模式下，已下载剧本可完成「触发 → 任务 → 提交 → 结算」全流程，恢复网络后自动同步 |
| AR | 至少 3 类可识别对象（建筑纹样 / 雕塑 / 文物说明牌）识别成功率 ≥ 90%，且能与任务判定联动 |
| 定位 | 城市峡谷与景区室内场景下，节点触发误报率 ≤ 5%，漏报率 ≤ 5% |
| 城市网络 | 至少 1 座城市提供跨 3 个景区的完整故事线，且进度与徽章跨景区累计正确 |
| 合规 | 通过儿童个人信息保护的第三方合规评审；家长可一键导出/删除孩子的全部数据 |
| 家长端 | 家长可查看周报并设置游玩时长上限，超限时 C 端给出友好提示 |
| 全球化 | 至少 1 个海外城市上线本地化剧本，且支付、时区、语言均正确 |

### 5.2 风险提示

| 风险 | 影响 | 建议 |
|---|---|---|
| 上传真实图片会引入存储与审核成本 | 项目复杂度上升 | 先从 1 个节点试点，明确存储上限与审核 SLA |
| 向量检索依赖模型服务 | 离线可跑的承诺被削弱 | 保留 `LIKE` 作为降级路径，向量库本地化（如 sqlite-vec） |
| 多语言会牵动剧本内容 | 内容量翻倍 | 先做 UI 层，内容层由 AI 生成时按语言产出 |
| 清理残留文件可能影响历史排查 | 丢失调试脚本 | 移入 `tests/legacy/` 而不是直接删除 |
| AR 与真实地图依赖设备能力 | 低端机体验下降 | 全部做「能力探测 + 优雅降级」 |

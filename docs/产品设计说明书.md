### 1.1 产品不是什么

- 不是普通儿童玩具：实体潮玩的真正价值在于**它绑定了一个持续更新的景区内容库与成长档案**。
- 不是景区导览 App：导览解决「怎么走」，游伴解决「为什么值得走、走完孩子得到了什么」。
- 不是一次性打卡：每次任务通过都会累加五维成长值、可能解锁徽章、推进剧本章节，形成可回访的长期记录。

## 2. 核心用户与痛点

### 2.1 三类核心用户

| 用户 | 细分 | 真实特征（来自种子数据） | 需求 |
|---|---|---|---|
| 孩子 | 4–8 岁「亲子探索」 | 例：熊猫小分队（Lv.3 探索家，成长值 560，旅行 18 天）、西湖小诗人（Lv.2 小旅人，214） | 看得见、摸得着、能立刻做到的动作；语言简单、有拟声词 |
| 孩子 | 8–12 岁「少年冒险」 | 例：小小探险家（Lv.3 探索家，361）、苗岭小勇士（Lv.5 少年冒险家，1120） | 有悬念、有目标、需要观察与简单推理 |
| 孩子 | 12+「沉浸剧本」 | 例：星际旅行家（Lv.4 资深探险家，842） | 有角色、有立场、有取舍；史料与实物互相印证 |
| 家长 | 家庭账号 | `users.family_name`：如「小小探险家 · 王家」「大唐小探员 · 郑州刘家」 | 安全、可控、可看到孩子的成长轨迹；愿意为「有教育内容的陪伴」付费。**已落地为「家长模式」两个界面**（家庭成长概览 / 单次旅行报告，见 5.5 节） |
| 景区 | 景区运营方 | `parks` 12 座（5 座已点亮）、`cooperations` 4 条合作记录 | 提升停留时长与复游率；把「到此一游」变成「有内容可讲」 |

年龄分层枚举（`AGE_BANDS`）：

| key | 标签 | 玩法定位 |
|---|---|---|
| `4-8` | 亲子探索 | 每次只做一件事，重点在「找到」与「看见」 |
| `8-12` | 少年冒险 | 线索层层递进，观察真实环境并做简单推理 |
| `12+` | 沉浸剧本 | 有角色与立场，允许开放式结局，形成自己的判断 |

### 2.2 三类痛点

| 痛点 | 具体表现 | 游伴的解法 | 落地位置 |
|---|---|---|---|
| 孩子「走不动、看不懂」 | 景区对孩子是「一堆看不懂的老房子」，家长讲不动、也讲不准 | 把景区素材变成**孩子能执行的动作**：数一数、找一找、拍一拍、比一比 | `tasks` 表 63 条任务；`app/engines/story_engine.py` 的 `AGE_PLAY` |
| 家长「陪玩无抓手」 | 想让孩子学到东西，但缺少结构化的互动脚本 | 五维成长值 + 10 级称号 + 24 枚徽章，把「玩过」变成**可积累的成长档案**；家长模式给出**这次学到了什么**与**回家可以问什么** | `user_growth`、`badges`、`user_badges`、`utils.level_of()`、`app/engines/parent.py` |
| 景区「内容一次性」 | 导览词、指示牌更新成本高，游客听完就走，没有复访理由 | AI Story Engine 用景区资料**批量生成剧本**，一次录入持续复用 | `materials` 439 条已入库素材 + `app/engines/story_engine.py` |

## 3. 产品结构

产品能力的五层结构，自下而上依次是「买得到 → 被认领 → 会走路 → 有故事 → 有成长」：

```
① 实体潮玩        阿游（城市限定款 / 基础款）
   characters(1) · skus(6) · activation_codes(5)
        ↓ 开箱激活，绑定数字身份
② 数字身份        users / devices / user_growth
   等级 · 五维成长值 · 家庭归属 · 伙伴昵称与装扮
        ↓ 走进景区
③ 旅行能力        parks(12) · 地理围栏 · 旅行地图 · 故事点附近推荐
   geo.py: haversine / find_park / locate_nodes
        ↓ 触发剧情
④ 故事能力        scenarios(6) · chapters(23) · nodes(37) · tasks(49)
   story.py: 节点三态 / 顺序解锁 / 章节推导
   story_engine.py: 素材 → 世界观 → 章节 → 节点 → 任务 → 奖励
        ↓ 完成任务
⑤ 成长能力        成长五维 · 10 级称号 · 24 枚徽章 · 装扮装备
   growth.py: 四种判定 / 保底成长 / 徽章三级解锁
```

| 层级 | 用户可感知的形态 | 数据规模（基础种子状态） |
|---|---|---|
| ①实体潮玩 | 阿游 · 大唐/皇家/西湖/熊猫/飞天/基础款 | SKU 6 款，已激活合计 128,601 台 |
| ②数字身份 | 「小小探险家 Lv.3 探索家 · 361 成长值」 | 用户 6 个、设备 2 台、五维 30 行 |
| ③旅行能力 | 「正在西安等你 · 附近有 2 个故事待开启」 | 景区 12 座，5 座已点亮 |
| ④故事能力 | 「大唐密令 第 3 章 密令现世 6/10 = 60%」 | 剧本 8 个、章节 31 章、节点 51 个、任务 63 条 |
| ⑤成长能力 | 「我的徽章 8 / 24」 | 徽章 24 枚、装扮装备 11 件 |

## 4. 核心闭环

### 4.1 设计定义（商业计划书 P10）

```
  位置（GPS / NFC / QR）
        ↓
  识别（进入景区围栏 → 找到可达剧情节点）
        ↓
  AI 角色主动出现（阿游开口，不是用户去找入口）
        ↓
  任务（观察 / 寻找 / 拍摄 / 解谜，四种判定方式）
        ↓
  剧情（章节推进、支线展开、章节状态从 now 变 done）
        ↓
  奖励（成长值 + 徽章 + 称号 + 装备）
```

### 4.2 本项目如何实现

| 环节 | 实现方式 | 关键代码 / 接口 |
|---|---|---|
| 位置 | 前端上报经纬度；未上报时使用景区坐标 + 演示偏移 `(0.0011, -0.0009)`（约 140m） | `POST /api/c/locate`、`GET /api/c/home`；`c_end.DEMO_OFFSET` |
| 识别 | 先按景区级围栏命中景区（半径 × 1.5 容差），再在**可达节点**中做节点级围栏判定 | `geo.find_park()`、`geo.locate_nodes()` |
| AI 角色主动出现 | `triggered` 数组直接带回节点的 `ai_dialog`、`story_text`、`hint` 与 `task`，前端弹节点剧情页；首次到访还会写入动态 | `c_end.locate()`；`events(type='node')` |
| 任务 | `verify_mode` 四态判定，计数型任务按 `target_count` 累计 | `growth.judge()` / `growth.submit()` |
| 剧情 | 节点全部任务完成 → 节点 `done` → 解锁下一个节点的触发资格 | `growth.node_is_done()`、`story.available_nodes()` |
| 奖励 | `reward_growth` 五维增量 + `reward_badge_id` / 剧本徽章 | `growth.add_growth()`、`growth._try_unlock_badge()` |

触发规则原文（`app/engines/geo.py`）：

> `haversine(user, node) <= node.radius_m` 即触发节点；景区级围栏允许 `radius_m × 1.5` 容差，避免演示坐标刚好落在边界外。

「附近」判定为 `radius_m × 8` 以内（`locate_nodes` 中实际使用 `elif d <= radius * 8`），用于前端展示「附近还有故事」。

### 4.3 顺序推进规则：前置节点解锁

这是本项目区别于「同一批节点同时可触发」的关键规则，实现于 `app/engines/story.py` 的 `available_nodes()`：

```
available_nodes(user, scenario):
    对剧本内按 idx 升序的每个节点 n:
        若 n 已完成 → 跳过
        取所有 idx < n.idx 的节点为前置节点
        若全部前置节点 node_is_done() → n 进入「可达」列表
```

配套的 `locked_reason()` 会给出人类可读的原因，前端直接展示：

```
"需要先完成「神秘来信」"
```

`POST /api/c/locate` 的响应结构因此分为三组，正好对应三种用户感知：

| 字段 | 含义 | 前端表现 |
|---|---|---|
| `triggered` | 可达 + 在节点围栏内 | 弹出节点剧情页，附带 `first_visit` 与 `task` |
| `nearby` | 可达但尚未进入围栏（≤ radius × 8） | 「前面 340m 有个『铜钱线索』，我们走过去看看好不好？」 |
| `locked` | 不可达（前置未完成） | 「需要先完成『密令现世』」，最多返回 3 条 |

> **为什么必须按顺序**：同一景区内多个节点常常落在极近的坐标（例如大雁塔节点 #1/#2/#5/#6/#9/#10 共用 `34.2186, 108.9644`）。若不做前置解锁，一次定位会同时触发多个节点，孩子会看到互相矛盾的剧情。顺序解锁保证了「一次只讲一个故事」。

### 5.2 开箱激活流程

线下到线上的 7 步，以及本项目在每一步的实现方式：

| # | 步骤 | 本项目实现 | 位置 |
|---|---|---|---|
| 1 | 打开包装，取出潮玩与激活卡 | 线下物料（原型外） | — |
| 2 | 输入激活码 | 开箱引导输入框，默认填入 `YB-XA-2026-0001`，并提供「一键填入」 | `web/c/index.html` `#obCode` / `#obFill` |
| 3 | 校验激活码 | `activation_codes.code` 唯一查询；无效返回 404「激活码不存在或已被使用」 | `POST /api/c/activate` |
| 4 | 给伙伴取名 | `nickname`，最长 8 字，默认「阿游」 | `ActivateReq.nickname` |
| 5 | 建立家庭与数字身份 | 新建 `users`（`family_name` 默认「小小探险家 · 新朋友」），初始化 `user_growth` 五维为 0 | `c_end.activate()` |
| 6 | 绑定潮玩设备 | 写 `devices`（`status='activated'`、`online=1`）、`activation_codes.used=1`、`skus.activated +1`、写一条 `events(type='device')` | `c_end.activate()` |
| 7 | 阿游开口 → 进入旅伴首页 | 返回 `greeting`「你愿意带我一起去看看这个世界吗？」，前端进入首页并预热剧本 | `c_end.activate()` + `web/c/app.js` |

### 5.3 节点剧情页（本项目延展）

原型只有五个 Tab，本项目新增了**独立的节点剧情执行页**（`web/c/index.html` 的 `#page-node` 子页）：

1. 从首页「附近的故事点」、对话任务卡、定位触发结果均可进入；
2. 页头显示节点名与 `type_label`（如 `STORY NODE · 当前`）；
3. 正文展示 `story_text`（剧情）与 `ai_dialog`（阿游的话）；
4. 任务区展示任务类型、`target_count` 进度（`1/3`）、提示 `hint`；
5. 提交后弹出结果层：通过/未通过反馈、成长值增量、徽章弹出、`next_node` 提示。

若某节点缺少任务映射，前端会退回用一次位置上报（`/api/c/locate`）来兜底触发（`web/c/app.js` 的 `openNodeById()`）。

### 5.4 换装抽屉（本项目延展）

- `GET /api/c/wardrobe` 返回 `items`（服装）与 `gear`（装备）两组；每条含 `owned` / `unlocked` / `current`。
- `POST /api/c/wardrobe/equip` 装备；若尚未拥有会**自动解锁**（`unlocked_now: true`），保证演示不卡死。

### 5.5 家长模式 · 成长报告（本项目延展）

#### 定位

商业计划书 P04 把家长列为三大用户之一：「想让孩子玩得开心，也希望旅行有内容，
但缺少好的亲子体验工具。」**两个原型都没有家长视角的任何界面**——C 端 5 个页面
全部是孩子视角，B 端是景区视角。家长模式由这条痛点直接推导而来，
回答家长真正会问的两个问题：

| 家长的问题 | 对应界面 |
|---|---|
| 「孩子这趟玩得怎么样？有没有长进？」 | **家庭成长概览**（`GET /api/c/parent/summary`） |
| 「今天到底学到了什么？回家我能跟他聊什么？」 | **单次旅行报告**（`GET /api/c/parent/report`） |

设计原则：**全部由数据库中的真实记录推导，不编造数字**。

#### 界面一：家庭成长概览

`GET /api/c/parent/summary?user_id=1`

| 区块 | 内容 | 真实取值（演示账号） |
|---|---|---|
| 孩子档案 | 昵称 / 等级 / 称号 / 成长值 / 年龄段 / 旅行天数 | 小小探险家 · Lv.3 探索家 · 361 · 8-12 少年冒险 · 12 天 |
| 6 项指标 | 走过的城市 / 完成的剧本 / 探索的剧情点 / 完成的任务 / 获得的徽章 / 累计探索时长 | 5/12 座 · 3/7 个 · 6/51 个 · 7 个 · 8/24 枚 · 94 分钟 |
| 五维画像 | 五维数值 + 一句话解读 | 探索78 创造62 观察85 知识70 勇气66 →「孩子在『观察』上表现最突出（85），『创造』相对最少（62），整体发展比较自然。」 |
| 近 7 天活跃 | 每天通过的任务数（真实统计） | 合计 9 个 / 峰值 9 |
| 近期徽章 | 最近获得的 6 枚（含获得时间） | — |
| 进行中的剧本 | 按最近游玩排序 | 5 个 |
| **亲子共玩建议** | 规则生成，最多 4 条 | 见下 |

**建议的规则来源**（`app/engines/parent.py::family_summary`，按顺序各取一条）：

1. 五维中**最低的两项** → 配 `DIM_ADVICE` 里写好的陪玩方法
   （如「创造」→「鼓励孩子把旅途中看到的东西画下来、讲出来，或者自己编一个后续剧情。」）
2. **下一座未点亮且有剧本的城市** → 「下一站可以去云南」+ 该剧本已就绪的说明
3. **当前可获取但尚未获得的徽章**（`badges.scenario_id` 指向 `status='online'` 的剧本）→「再完成一个剧本就能拿到『雨林探险家』」

这样家长看到的建议永远指向**真实存在、现在就能做**的事，而不是泛泛的育儿话术。

#### 界面二：单次旅行报告

`GET /api/c/parent/report?user_id=1&scenario_id=1`（先由 `/parent/reports` 列出可查看的剧本）

| 区块 | 内容 | 真实取值（《大唐密令》） |
|---|---|---|
| 汇总 | 已探索 / 已完成 / 总节点 / 百分比 / 状态 / 完成章节 / 完成任务 / 估算时长 / 起止时间 | 6 / 4 / 10 · 60% · 进行中 · 2/5 章 · 7 个任务 · 94 分钟 |
| 章节结构 | 每章的节点与状态 | 5 章 |
| 剧情时间轴 | 到访记录 + 任务提交合并按时间排序 | 15 条 |
| 本次成长累计 | 各维度增量之和（按剧本归集） | observe+68 knowledge+44 explore+42 courage+20 |
| 获得的徽章 | 该剧本相关的徽章 | — |
| **知识点反查** | 这次真正接触到的知识 | 3 条（见下） |
| **回家提问** | 3 个问题 | 见下 |

**知识点是怎么反查出来的**（`_knowledge_for`）：

```
孩子实际到访过的节点
   ↓ 取节点的 place（如「大雁塔」「钟楼」）
   ↓ 在该景区素材库中检索：materials.title LIKE '%place%' OR tags LIKE '%place%'
   ↓ 命中则取该素材的前两句作为「知识点」，并标注来源节点
   ↓ 未命中时退化为：从节点剧情文案抽一个 2-4 字关键词，在素材正文中检索
   ↓ 同一素材只出现一次，最多 6 条
```

真实结果（可直接复现）：

| 来源节点 | 反查到的知识点 | 分类 |
|---|---|---|
| 抵达大雁塔 | 大雁塔塔影的传说 | 民间传说 |
| 大唐不夜城 · 铜钱线索 | 大唐不夜城步行街路线 | 景区地理 |
| 钟楼 · 时空回响 | 钟楼与城墙的空间关系 | 景区地理 |

> 这条链路是家长模式的价值核心：**孩子走过的每一处，都能对应回景区里一条真实的资料**，
> 而这条资料同时又是 AI Story Engine 生成剧本时的语料来源——「资料 → 剧本 → 体验 → 报告」形成闭环。

**3 个回家提问是怎么生成的**（`_questions_for`，固定 3 条）：

| # | 规则 | 真实结果 |
|---|---|---|
| ① | 取孩子**最近一次通过**的任务，问是否还记得答案 | 今天你完成了「找出塔身上 3 个特殊符号」，你还记得答案是什么吗？ |
| ② | 取**最近到访**的节点，问第一印象与后来的新发现 | 在大雁塔，你第一眼注意到的是什么？有没有什么是后来才发现的？ |
| ③ | 从该剧本所属景区素材库取一条知识点，让孩子复述给家长听 | 考考你：关于「关中平原的地理形胜」，你能用自己的话讲给爸爸妈妈听吗？ |

第 ③ 条在素材缺失时退化为开放式想象题：「如果让你给这个故事编一个新结局，你会怎么编？」

#### 统计口径

| 指标 | 口径 |
|---|---|
| 走过的城市 | 有进度的剧本所属景区**去重**计数（`of` = 景区总数 12） |
| 完成的剧本 | `progress.status = 'done'` 的条数（`of` = **非草稿**剧本数，当前 7） |
| 探索的剧情点 | `node_visits` 条数（`of` = 节点总数 51） |
| 完成的任务 | `task_submissions` 中 `passed = 1` 的**去重 task_id** 数 |
| 累计探索时长 | 实际通过的任务在 `tasks.avg_minutes` 上求和；无记录时按 12 分钟/任务估算 |
| 近 7 天活跃 | 按 `submitted_at` 的日期分组统计**通过**的任务数 |

#### 接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/c/parent/summary` | 家庭成长概览 |
| GET | `/api/c/parent/reports` | 可查看报告的剧本列表 |
| GET | `/api/c/parent/report` | 单次旅行报告（需 `user_id` + `scenario_id`） |

契约细节见 [`API.md`](API.md) 的 **1A 节（1.12 / 1.13 / 1.14）**。

### 8.1 四类任务 × 四种判定方式

`TASK_TYPES`（四类）与 `verify_mode`（四种判定）正交组合：

| 类型 \ 判定 | `auto` 到达即过 | `answer` 精确作答 | `keyword` 关键词 | `photo` 拍照 |
|---|---|---|---|---|
| `observe` 观察 | 领取徽章类 | 数层数、数兽数 | 找纹样、数垛口 | — |
| `find` 寻找 | — | 找第几个垛口 | 找材料、找殿名 | 找三枚铜钱（计数） |
| `photo` 拍摄 | — | 数舞马数量 | 写诗句、守护宣言 | 拍纹样 / 足迹 / 梯田 |
| `solve` 解谜 | — | 钟声几下、圆孔几个 | 排列线索、推断含义 | — |

基础种子状态的 63 条任务分布（按 `seed_data.py` 统计）：

| 维度 | 分布 |
|---|---|
| 任务类型 | 观察 25 · 解谜 19 · 拍摄 10 · 寻找 9 |
| 判定方式 | `keyword` 28 · `answer` 17 · `photo` 10 · `auto` 8 |
| 年龄层 | `8-12` 56 · `4-8` 5 · `12+` 2 |
| 计数型（`target_count > 1`） | 7 条 |

判定细节（`growth.judge()`）：

| mode | 通过条件 | 未通过反馈 |
|---|---|---|
| `auto` | 提交即通过，`user_answer = "已到达"` | — |
| `photo` | `photo_note` 非空 | 「还没有拍下照片哦，先找到目标再按快门～」 |
| `answer` | 归一化后与 `answer` 完全相等，或命中 `keywords` 任一项 | 「再仔细看看哦，答案就藏在眼前～」 |
| `keyword` | `answer` 或任一关键词**包含于**用户输入 | 「差一点点！换个角度再试一次吧 💪」 |

归一化规则：`strip().lower()` 并去掉半角/全角空格（`growth._norm()`），因此「第 37 个」「第37个」等价。

通过反馈文案从 `FEEDBACK_OK` 中选取，例如「太棒了！你观察得真仔细 ✨」；未通过从 `FEEDBACK_FAIL` 中选取。

### 8.2 计数型任务（`target_count`）

- `task_submissions` **每通过一次写一行**，`task_done_count()` 用 `COUNT(*) ... AND passed = 1` 累计进度。
- 典型例子：「在不夜城找回三枚古铜钱」（`find` / `photo` / `target_count = 3`）。真实端到端结果：

```
第1次提交  pass=True progress={'done': 1, 'total': 3} badge={'id': 9, 'name': '铜钱收藏家', …}
第2次提交  pass=True progress={'done': 2, 'total': 3} badge=None
第3次提交  pass=True progress={'done': 3, 'total': 3} badge=None
```

- 已达标的重复提交直接返回完成态：「这个任务你已经完成啦 ✨」，不重复发放成长值。
- 「找出塔身上 3 个特殊符号」（`observe` / `keyword` / `target_count = 3`）是演示账号的**当前任务**，进度 1/3。
- 全库共 **7 条**计数型任务（`target_count > 1`），例如《雨林寻踪》的
  「数出雨林一共有几层结构」（`target_count = 2`）与「拍下三种不同的雨林植物」（`target_count = 3`）。

### 8.3 节点完成条件

`growth.node_is_done()`：节点下**所有启用任务**都达到 `target_count` 才算节点完成；若节点没有任何任务（纯剧情 / 入口），则**到访即算完成**。节点完成后会刷新 `progress`（章节、百分比、状态），并可能补发徽章。

## 9. 年龄分层玩法

设计原则（商业计划书 P13）：**一座景区，可以拥有不同年龄的故事**。实现方式有两条：

1. **同一节点挂多条不同年龄层的任务**（`tasks.age_band`）；
2. **不同年龄层生成不同剧本**（`story_engine.AGE_PLAY` 提供世界观前缀、叙事要求、任务动词、奖励名）。

`AGE_PLAY`（`app/engines/story_engine.py`）：

| 年龄层 | 玩法 | 世界观前缀 | 任务动词 | 默认奖励 |
|---|---|---|---|---|
| `4-8` | 亲子探索 | 这是一个关于「发现」的故事。 | 数一数 / 找一找 / 拍一拍 / 比一比 | 小小发现家 🌟 |
| `8-12` | 少年冒险 | 这是一个关于「解谜」的故事。 | 观察细节 / 搜集线索 / 拍摄记录 / 推理判断 | 少年解密者 🔎 |
| `12+` | 沉浸剧本 | 这是一个关于「选择」的故事。 | 考据比对 / 逻辑推演 / 影像取证 / 观点论证 | 深度考据家 📚 |

### 9.1 《大唐密令》中的真实分层例子

同一个节点同时承载不同年龄层的任务（数据来自 `seed_data.XIAN_TASKS` 与 `seed_data.EXTRA_TASKS`）：

| 节点 | 8-12 岁任务 | 4-8 岁任务 | 12+ 任务 |
|---|---|---|---|
| #3 大唐不夜城 · 铜钱线索 | 在不夜城找回三枚古铜钱（寻找 / 拍照 / 目标 3）· 算出三枚铜钱的年号先后顺序（解谜 / 关键词） | — | — |
| #4 钟楼 · 时空回响 | 数清钟声响了几下（解谜 / 答案 `6`） | **听钟声，数一数响了几下**（观察 / 答案 `6`）—— 同一现象只要求「听」和「数」 | — |
| #5 密令现世 | 找出塔身上 3 个特殊符号（观察 / 关键词 / 目标 3） | — | **推断密令真正想告诉你的是什么**（解谜 / 关键词「观察,细心,认真,看懂」） |
| #7 城墙 · 守城之谜 | 找到城墙上唯一的暗号垛口（寻找 / 答案「第37个」） | 数一数城墙的垛口有几个（观察 / 关键词「多,很多,数不清」）—— 由「精确答案」降级为「开放描述」 | — |
| #8 陕西历史博物馆 · 文物密码 | 数出银壶上舞马的数量（拍摄 + 答案 `5`） | 找出展厅里最亮的一件文物（寻找 / 拍照）—— 由「数量」降级为「选择」 | — |
| #9 终极谜题 | 按正确顺序排列四条线索（解谜 / 关键词） | — | **推断密令真正想告诉你的是什么**（解谜，奖励 `knowledge 20 / courage 14 / create 10`） |

可以看到三个明确的分层手法：

1. **动作降级**：12+ 要「排序 + 推断」，4-8 只要「听 + 数」；
2. **答案开放化**：8-12 要求「第 37 个」这样精确的答案，4-8 允许「很多、数不清」这类描述性回答；
3. **奖励梯度**：`_reward_for()` 按年龄层放大奖励（4-8 ×1.0、8-12 ×1.3、12+ ×1.6），12+ 的挑战更高、回报也更高。

## 一分钟启动

**环境要求**：Python 3.10+（本项目在 Python 3.14 上开发验证）。**不需要 Node.js，不需要数据库服务，不需要联网。**

```bash
# 1) 安装依赖（只有 3 个包）
python -m pip install -r requirements.txt

# 2) 启动（首次自动建库并播种演示数据）
python run.py
```

Windows 用户也可以直接双击 **`启动游伴AI.bat`**（会自动检查环境、安装依赖、打开浏览器）。

其他命令：

```bash
python run.py --reseed        # 重新播种演示数据（清空并重建）
python run.py --port 8080     # 指定端口
python run.py --host 0.0.0.0  # 指定监听地址
python tests/e2e_check.py     # 接口端到端自检（49 项）
python tests/inspect_data.py  # 数据体检（对照原型逐项核对）
```

### 关于端口（请先读这一段）

默认端口是 **8770**（刻意避开常被其它项目占用的 8000）。

**如果该端口已被占用，启动器会自动向上寻找一个空闲端口，并在终端明确提示实际地址：**

```
[游伴 AI] 端口 8770 已被占用。已自动改用 8771。
```

> 实际启动会落在 8771）。也可以固定端口：
> Windows `set YOUBAN_PORT=9000` · macOS/Linux `export YOUBAN_PORT=9000`。

## 核心闭环如何落地

商业计划书 P10 的闭环，在代码里的真实实现路径：

```
位置上报 /api/c/locate
   ↓
geo.find_park()              景区级围栏（1.5 × radius_m 容差）
   ↓
story.available_nodes()      ★ 顺序解锁：前置节点全部完成才「可达」
   ↓
geo.locate_nodes()           Haversine ≤ node.radius_m → 触发
   ↓
growth.ensure_visit()        记录首次到访，写 events 实时动态
   ↓
返回 triggered[]             AI 角色台词 + 剧情文案 + 任务卡
   ↓
POST /api/c/task/{id}/submit 四种判定方式
   ↓
growth.submit()              成长值累加 → 等级提升 → 徽章解锁 → 进度刷新
```

### 关键设计：顺序解锁

原型没有约定「哪个节点该在什么时候触发」。本项目补上了这条规则：
**节点必须等它的所有前置节点（`idx` 更小）完成后才「可达」**。

否则同一个景区里多个节点坐标相近时，孩子会一次性收到一堆任务。
现在 `/api/c/locate` 只会返回**当前该做的那一个**，并把其他节点连同
「需要先完成「xxx」」的原因一起返回，前端可以友好提示。

### 任务判定（`app/engines/growth.py`）

| 判定方式 | 行为 | 典型任务 |
|---|---|---|
| `auto` | 到达即通过 | 领取徽章 |
| `answer` | 精确匹配答案或命中关键词 | 数出塔的层数、数清钟声 |
| `keyword` | 命中任一关键词即通过 | 找出砖纹符号、排列线索顺序 |
| `photo` | 提交照片说明即通过 | 拍摄唐代纹样、找回三枚铜钱 |

- 计数型任务用 `target_count` 表示需要完成几次（如「找回三枚古铜钱」`target_count=3`），
  每次提交累计 1 次，满额才算完成。
- 未通过时给 **20% 保底成长值**（至少 1 点），避免孩子挫败。
- 等级阈值：`0/100/300/600/1000/1600/2400/3600/5200/7200` →
  初识伙伴 / 小旅人 / 探索家 / 资深探险家 / 少年冒险家 / 城市猎人 / 故事收藏家 / 传说旅人 / 星图守护者 / 世界发现者。
- 徽章解锁优先级：任务自带 → 节点自带 → 剧本「结算节点」完成。

## AI Story Engine

对应商业计划书 P12。**默认使用内置离线规则引擎，无需联网、无需 API Key 即可完整演示。**

### 生成流程

```
景区素材（materials 表，439 条已入库）
   ↓ ① 按分类取样（优先本景区，不足时同城/全库补齐）
   ↓ ② 构建世界观（引用真实素材内容 + 按年龄层调整叙事基调）
   ↓ ③ 生成章节（7 个章节模板轮转）
   ↓ ④ 生成剧情节点（八点结构：入口/古建筑/古树/博物馆/山谷/观景台/隐藏地点/终极任务）
   ↓ ⑤ 生成任务（观察 → 寻找 → 拍摄 → 解谜 轮转，目标数按类型分配）
   ↓ ⑥ 生成奖励（年龄层主徽章 + 城市记忆 + 连环解密者 + 非遗传承人）
   ↓ ⑦ 来源溯源（每个节点标注引用的素材 ID 与标题）
   ↓ ⑧ 落库为 draft 剧本（节点坐标自动在景区附近抖动生成 + 画布自动布局 + 连线）
```

### 五种生成模式

| 模式 | 输出 |
|---|---|
| `mainline` | 世界观 + 剧本名 + 章节结构 |
| `task` | 仅剧情节点与任务 |
| `dialog` | 仅阿游台词、剧情文案与提示 |
| `reward` | 仅奖励体系 |
| `full` | 全部内容，并直接入库为草稿剧本 |

### 年龄分层（商业计划书 P13）

| 年龄 | 玩法 | 叙事基调 | 主徽章 |
|---|---|---|---|
| 4-8 | 亲子探索 · 寻找 / 观察 / 拍照 | 语言简单有节奏，每次只做一件事 | 小小发现家 🌟 |
| 8-12 | 少年冒险 · 任务 / 解谜 / 剧情选择 | 有悬念与目标，线索层层递进 | 少年解密者 🔎 |
| 12+ | 沉浸剧本 · 推理 / 协作 / 角色 | 有角色有取舍，允许开放式结局 | 深度考据家 📚 |

同一条规则也体现在种子数据里：《大唐密令》的钟楼节点同时挂着
**12+ 的解谜任务**（数清钟声响了几下）和 **4-8 的观察任务**（听钟声数一数），
这就是「同一景区 × 不同年龄 × 不同剧情」。

## 接入真实大模型

AI Story Engine 与阿游对话都预留了真实大模型分支。配置三个环境变量即可切换：

```powershell
# Windows PowerShell
$env:YOUBAN_LLM_BASE_URL = "https://api.deepseek.com/v1"
$env:YOUBAN_LLM_API_KEY  = "sk-xxxxxxxx"
$env:YOUBAN_LLM_MODEL    = "deepseek-chat"
python run.py
```

```bash
# macOS / Linux
export YOUBAN_LLM_BASE_URL="https://api.deepseek.com/v1"
export YOUBAN_LLM_API_KEY="sk-xxxxxxxx"
export YOUBAN_LLM_MODEL="deepseek-chat"
python run.py
```

- 使用 **OpenAI 兼容**的 `/chat/completions` 接口，只依赖标准库 `urllib`，不引入额外依赖。
- 大模型需要返回结构化 JSON；系统提示词在 `app/engines/story_engine.py` 的 `LLM_SYSTEM_PROMPT`。
- **调用失败会自动回退到离线规则引擎**，并在返回结果里说明回退原因，不会让界面报错。
- 通过 `GET /api/admin/ai/engine` 可查看当前实际使用的引擎与配置状态。

**技术选型理由**

| 决策 | 理由 |
|---|---|
| FastAPI + Pydantic | 自带 OpenAPI/Swagger，请求校验与文档零成本 |
| SQLite | 单文件、零运维、随项目即走；`sqlite3` 是标准库 |
| 原生前端，不用框架 | 完全离线可用、无需 npm/构建，双击即可运行 |
| AI 引擎走离线规则 + 大模型分支 | 保证任何人拿到都能立刻跑通，同时保留真实生成能力 |
| 只依赖 3 个第三方包 | 降低安装失败概率（`fastapi` / `uvicorn` / `pydantic`） |

### 自检与验证

**推荐用统一入口一次跑完五套验证**（自动选空闲端口起服务、按正确顺序执行、跑完自动恢复数据）：

```bash
python tests/run_all.py --start        # 自动启动服务并跑完全部五套
python tests/run_all.py --no-browser   # 跳过真实浏览器验证（不需要 Playwright）
python tests/run_all.py --base http://127.0.0.1:8801   # 对已运行的服务执行
```

执行顺序（顺序很重要，因为部分检查会写库）：

```
重置演示数据
  → ① contract_check.py   契约一致性（只读）
  → ② final_audit.py      交付一致性终检（只读，需干净演示数据）
  → ③ browser_check.py    真实浏览器验证（开头自行重置数据）
  → ④ e2e_check.py        接口端到端自检（会写库）
  → ⑤ round2_check.py     第二轮功能自检（会写库）
  → ⑥ inspect_data.py     数据体检（刷新 tests/_inspect.txt）
  → 恢复演示数据
```

也可以单独运行：

```bash
python tests/contract_check.py     # → tests/_contract.txt
python tests/final_audit.py        # → tests/_audit.txt
python tests/browser_check.py      # → tests/_browser.txt（截图到 tests/shots/）
python tests/e2e_check.py          # → tests/_report.txt
python tests/round2_check.py       # → tests/_round2.txt
python tests/inspect_data.py       # → tests/_inspect.txt（数据体检）
python tests/port_check.py         # 端口探测与自动回退自检
```

> ⚠️ `e2e_check.py` 与 `round2_check.py` 会**真实写入数据库**（激活新账号、提交任务、
> 新建剧本/节点/素材、执行 AI 生成），因此运行后演示账号状态会变化。
> `browser_check.py` 与 `round2_check.py` 会在开始时**自动重置为初始演示状态**，所以它们可重复、结果确定。
> 想在任何时候恢复初始状态，执行 `python run.py --reseed`。
>
> `browser_check.py` 需要额外安装 Playwright（`python -m pip install playwright && python -m playwright install chromium`），
> 属于可选的验证工具；**运行本项目本身不需要它**。

## 与原型的关系

**忠实还原**：品牌色（深夜蓝 `#0B1020` / 暖白 `#F5F1E8` / 沙金 `#E8B45A` / 森林绿 `#4FA08C` / 活力橙 `#F0873F`）、
C 端 5 大页面结构与组件、B 端 9 大模块与视觉、演示账号数值（Lv.3 / 361 / 8 徽章 / 60% 进度 / 1/3 任务）、
素材分类条数（128/96/42/61/78/34 = 439）。

**延展**（原型未覆盖）：

- 节点剧情执行页与完整的任务作答 → 判定 → 奖励反馈链路
- 顺序解锁机制与「为什么还不能触发」的友好提示
- 换装系统、会话恢复、演示账号接口
- AI Story Engine 生成向导（4 步流程 + 5 种模式）
- 《苗岭宝藏》《雨林寻踪》《园林谜题》三个剧本，补齐商业计划书 P17 的六城故事地图
- **家长模式**：家庭成长概览 + 单次旅行报告（含知识点反查与回家提问）——原型完全没有，由商业计划书 P04 的家长痛点推导
- **可观测性**：结构化请求日志、按端点聚合的运行指标、业务计数、`X-Response-Time`
- 统一测试入口 `tests/run_all.py` 与五套自动化验证
- 大模型接入预留与自动回退

**有意差异**（并在文档中说明原因）：剧本数 **8**（原型 5）、章节 **31**、节点 **51**（原型示例 10 个）、
任务数 **63**（原型 42）、后台统计数字改为按真实数据库实时计算（原型为静态示意数据）。
